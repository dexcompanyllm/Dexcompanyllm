# ROADMAP — 개발·매장 적용·상품화

Status: proposal. 일정·비용·기술 스택·출시일은 미확정이에요. 완료 조건으로 단계를 관리해요.

| 단계 | 실제 산출물 | 완료 조건 | 미리 하지 않을 일 |
|---|---|---|---|
| G0 기준 등록 | 공통 지침/디자인/제품/QA/Task | 등록 PR 검수·승인 main 반영 | 앱 완료/운영 배포 주장 |
| G1 인계·기술 확인 | 기존 코드 조사, stack/asset/license 표, 대표 LIVE spike | 실재하는 코드 위치·worker·테스트 명령 확인 | 근거 없는 스택 교체/전체 재구현 |
| G2 DEMO MVP | LIVE·브랜드·상품·검색·재고/위치 mock·맨눈/세션 | 적용 범위 P0 PASS, 가능한 빌드/실행 산출물 | 실상품/실재고처럼 소개 |
| G3 Android 검증 | Flip5/Tab 설치·테스트/수정 증거 | 각 기기 P0·성능/발열/세션 검수 | 기기 미보유 결과를 PASS로 처리 |
| G4 매장 파일럿 | 실상품 승인 asset, POS/재고 read adapter, 위치/관리자 최소 기능 | 1개 매장 E2E, 오류 복구·권한·rollback | 자동 재고 수정/결제/외부 발송 |
| G5 상품화 | 고객사/매장 설정, 배포/라이선스/지원·보안·접근성 패키지 | 권리/정책 검토, 운영 비용·SLA·계약/가격 승인 | 무검증 유료 플랜/자동 결제 활성화 |
| G6 확장 | 검증된 필요에 따른 통계·추천·다국어·기타 OS | 파일럿 근거로 우선순위 결정 | 기능 개수만 늘리는 확장 |

## 상품화 최소 관리 범위

고객사/매장별 취급 브랜드·상품/위치 설정, 상품 asset 버전·승인, 재고 연동 상태/마지막 갱신, 직원/관리자 권한, 기기 등록/상태, 앱 배포 버전과 rollback을 준비해요. 고객용 kiosk에 관리자 계정과 설정을 노출하지 않아요. 고객사별 데이터 분리는 화면 필터가 아니라 서버 권한 경계에서 검증해요.

초기에는 파일럿 1개 매장을 목표로 하되 데이터 키에 tenant/store를 두고 확장을 대비해요. 처음부터 복잡한 SaaS 청구/권한 메뉴를 모두 만들지는 않아요. 신규 과금·계약·대외 판매는 에던의 별도 결정이에요.

## 출시 전 미확인 항목

LENS ME 명칭/표장 사용 권한, 입점 브랜드/상품 이미지/렌즈 asset 허가, SDK/모델/폰트 라이선스, 실제 데이터 공급 계약, 개인정보 처리/보존/공용기기 안내, 현지 무인단말기 접근성 요구, 테스트 하드웨어/기기 잠금·원격 관리·보안 업데이트, 고객 지원/장애 복구를 확인해요. 이 문서는 법률 적합성 확인이나 상표 조사 완료 결과가 아니에요.

## 키오스크 사양 요청서

확정 시 OS/버전, native vs browser 실행 방식, 화면 inch/해상도/방향/배율, CPU/GPU/RAM/저장공간, 전면 카메라 모델/해상도/FOV/높이, 조명/역광, touch와 설치 높이/접근 공간, 네트워크/오프라인, scanner 유무, kiosk lock/MDM, 업데이트/rollback, 배포/인증 방식만 받아요. 없는 사양을 추정하지 않으며 하드웨어 미정은 DEMO/문서/독립 테스트를 막지 않아요.

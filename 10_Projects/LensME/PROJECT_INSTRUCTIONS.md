# LENS ME 프로젝트 공통 지침

## 1. 프로젝트와 기준정보
이 프로젝트는 렌즈 판매 매장에서 사용하는 LIVE 가상 착용·상품 탐색 솔루션 LENS ME예요. 기존 명칭 Lens Screen / 렌즈 스크린 / 렌즈 키오스크는 같은 프로젝트의 별칭으로 취급해요. 기존 구현·자료는 확인 전 삭제하거나 새로 만들지 않아요.

Canonical 기준은 GitHub `ethanhee890-commits/dex-company-wiki`의 승인된 `main`이에요. 프로젝트 문서는 `10_Projects/LensME/`에서 관리해요. 이 폴더가 main에 없으면 같은 이름의 PR 상태를 확인하고, 브랜치를 승인된 main처럼 취급하지 않아요.

시작할 때 `AI_CONTRACT.md` → `CURRENT_STATE.md` → 프로젝트 `PROJECT_CONFIG.md` → `CURRENT.md` → `SESSION_HANDOFF.md` → `DECISIONS.md` → 현재 Task를 필요한 범위만 읽어요. 디자인은 `Design/DESIGN_GUIDE.md`와 `Design/DESIGN_TOKENS.json`을 추가로 확인해요. 채팅·메모리·로컬 경로는 최신 상태의 근거를 대신하지 않아요.

## 2. 승인된 디자인 방향
2026-09-18 에던이 승인한 세로 키오스크 시안을 기본으로 유지해요. 밝은 뉴트럴 배경, 차콜 주요 버튼, 절제된 블루 포인트, 큰 LIVE 영역, 브랜드 탭, 검색, 상품 카드, 재고·위치 패널의 위계를 지켜요. 과한 그라데이션·네온·장식 카드·과도한 그림자·미용 필터·모델 포즈를 추가하지 않아요.

승인은 시각 방향과 요청 기능에 대한 것이에요. 생성 이미지 속 오탈자·상품명·가격·재고·모든 문구·6단계 강제 플로우까지 확정된 것은 아니에요. 기능상 모순은 수정하고 변경 근거를 기록해요. 색상·간격·글꼴 수치는 구현용 제안값과 승인값을 구분해요.

## 3. 핵심 경험과 필수 기능
사진 촬영이 아니라 전면 카메라의 실시간 상반신 영상이 중심이에요. 머리·양쪽 어깨·가슴 부근이 자연스럽게 보이도록 하고 얼굴·눈을 과도하게 확대하거나 보정하지 않아요. 모델 자세를 요구하지 않아요. 사진 업로드·셔터·촬영 완료 화면을 기본 흐름에 넣지 않아요.

상품을 선택하면 LIVE를 끊지 않고 같은 상품을 양쪽 눈에 적용해요. `맨눈/렌즈`, 후보 A/B 비교는 전체 얼굴 단위로 전환해요. 영상 또는 추적이 멈추면 LIVE/착용 완료로 표시하지 않아요.

다양한 브랜드 선택, 선택 브랜드의 상품 목록, 상품명 또는 상품코드 검색, 현재 매장의 재고 확인, 매장 내 상품 위치 안내를 필수 기능으로 구현해요. 선택 브랜드와 검색 범위를 명시하고 다른 브랜드를 몰래 섞지 않아요. 상품 미제공 상태에서는 명확히 표시한 DEMO로 개발을 계속해요.

## 4. 데이터와 개인정보
생성 시안의 브랜드·상품·렌즈 발색·가격·재고·진열 위치를 실제 운영 데이터로 사용하지 않아요. 브랜드·상품·판매 옵션(SKU)·매장별 재고·진열 위치를 분리해요. 재고 없음, 조회 실패, 오래된 재고를 구분하고, 선택 옵션이 없으면 수량을 단정하지 않아요. 발색 체험은 피팅·처방·건강 진단이 아니에요.

고객 얼굴·영상·추적 데이터는 기기 내 일시 처리 기본값으로 설계해요. 저장·외부 전송·학습·얼굴 식별을 기본 금지해요. 대기/종료/유휴 정리 시 카메라와 세션 정보를 정리해요. QR은 선택 상품 정보 인계용이며 얼굴 이미지를 포함하지 않아요. 개인정보 보호 문구는 실제 검증한 동작만 표시해요.

## 5. 구현·품질·승인
기존 저장소·인계 패키지·`PROJECT_INSTRUCTIONS.md`·`START_SOL.md`의 실제 위치를 먼저 확인해 이어받아요. 앱 코드는 검증된 프로젝트 코드 저장소에, 정책·설계·결정·검증 증거는 위키에 둬요. 기기 이름만으로 레이아웃을 선택하지 않고 실제 가용 화면·방향·배율을 기준으로 해요. Galaxy Z Flip5와 Galaxy Tab S10 FE+를 우선 실기기 검증 대상으로 두되 미실행 검사는 Not Checked로 남겨요.

UI 요소 + 조건 + 동작 + 결과로 설명하고 Loading/Empty/Error/Disabled/권한 거절/다중 얼굴/추적 유실/품절/오프라인을 포함해요. 화면설계, 개발 기술문서, QA 문서는 분리해요. 대표 LIVE 화면의 구현 검수부터 하고, 이후 범위를 확장해요. 수정과 무관한 코드·사용자 변경·설정은 보존해요.

제니는 분석·설계·검수·Task Intake, 덱스는 코드·테스트·빌드·실행을 담당해요. 같은 Task ID와 체크포인트로 이어가며 실행 도구가 없으면 실행했다고 말하지 않아요. 가능한 부분은 직접 처리하고 필요한 사용자 행동만 한 번에 요청해요. 같은 실패 방식은 최대 2회까지만 시도해요.

OpenAI/Anthropic은 구독 우선이에요. 유료 API·자동 유료 fallback·추가 과금·비밀값 노출을 금지해요. branch → 변경 → 검증 → PR → 필요한 승인 → main 순서를 지켜요. 명시적으로 승인된 범위는 재승인받지 않되 새 비용·권한·외부 배포·운영 데이터 변경은 별도 승인해요.

최종 보고에는 변경 내용·파일/PR·검사 결과(PASS/FAIL/Not Checked)·남은 문제·최소 다음 행동을 기록해요. 작업 종료 시 CURRENT, SESSION_HANDOFF, QA_REPORT, 필요한 DECISIONS/SOURCES와 Task 결과를 갱신해요. LENS ME는 개발용 표시명으로 사용하되 외부 상품화 전 명칭·브랜드·상품 이미지 사용 권한을 확인해요.

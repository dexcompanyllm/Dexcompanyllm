## confirmed

### PR #42375 — Windows sandbox uninstall cleanup

OpenAI merged PR #42375 on 2026-09-02 22:22:09 UTC.

The change records the authenticated sandbox owner, observes package-uninstall events across service restarts and session changes, serializes setup and cleanup, disables sandbox accounts and stops their processes before removing sandbox directories/firewall/WFP/hidden-user/account/group resources, restricts desktop-owned directory cleanup to pinned paths while impersonating the authenticated owner, and repairs interrupted cleanup before restoring network access.

The upstream patch also keeps replacement accounts disabled during interrupted-cleanup repair until required WFP protections are successfully restored and treats disabled-account startup failures as refreshable provisioning failures.

### PR #42377 — App Server realtime always available

OpenAI merged PR #42377 on 2026-09-02 22:32:19 UTC.

The change removes the per-thread `RealtimeConversation` feature check from `thread/realtime/start`, marks `features.realtime_conversation` as a removed compatibility setting, and documents that the legacy setting has no effect even when set to `false`. Upstream tests cover realtime startup after fork and cold resume with the legacy key absent, false, or true.

Therefore the old `false` value is no longer a reliable negative capability or security control.

### Issue #42376 — custom Responses provider scheduled-task compatibility signal

The official `openai/codex` repository opened issue #42376 on 2026-09-02 22:30:14 UTC with `bug`, `custom-model`, `app`, `app-server`, and `automations` labels.

The report reproduces on Codex Desktop `26.901.20858` with bundled CLI `0.153.0-alpha.5` and a custom Responses provider. An App Server standalone `function_call_output` generated by `automation_update` can omit `call_id`; the internal Codex extension accepts that shape, while a strict public Responses-schema provider rejects it before model output.

This is a confirmed official bug signal, not a maintainer-confirmed root cause or fixed-release statement. Maintainer-confirmed root cause, fix, affected non-prerelease stable, and first-party OpenAI impact remain unknown.

### inference

PR #42375 is security-positive for future Windows hosts because uninstall is a privileged destructive lifecycle. Removing only authenticated, pinned Codex-owned resources and keeping interrupted-repair accounts disabled until network protections return reduces stale-account, stale-rule, and path-confusion risk.

PR #42377 improves portability and reduces stale configuration across fork/resume, but availability is not authorization. Dex must stop treating `features.realtime_conversation = false` as a disable guarantee and instead enforce whether a Task is allowed to request realtime at the Dex authorization/capability layer.

Issue #42376 is a portability warning: an internal App Server history extension can be valid inside Codex yet invalid at a strict third-party Responses wire boundary. Provider adapters must validate target-provider schema rather than forwarding internal items blindly.

### proposal — tracked, not enabled

After the first official non-prerelease stable containing PR #42375, approved Windows-host E2E should verify:

- install/provision → service/session transition → uninstall leaves no expected Codex sandbox account/group/hidden-user/sandbox-dir/firewall/WFP residue;
- cleanup touches pinned Codex-owned paths only and preserves user files, project worktrees, canonical repositories, credentials, unrelated accounts and network rules;
- accounts are disabled and processes stopped before destructive cleanup;
- interrupted cleanup cannot restore login/network access before required restrictions are restored;
- reprovision restores state exactly once without duplicate users, rules, or directories;
- wrong package identity, authenticated owner, stale uninstall event, or path ambiguity fails closed with unrelated mutation 0;
- uninstall/reinstall cannot broaden permissions or bypass Dex approval/project registry.

After the first official non-prerelease stable containing PR #42377, Runtime #34 App Server/surface E2E should verify:

- realtime availability comes from the effective stable App Server contract rather than the removed legacy flag;
- legacy `false` is never treated as a security control or proof of feature absence;
- Dex calls realtime only for an explicitly required and authorized workflow;
- fork/resume/reconnect preserves Task/attempt lineage and creates no duplicate Task, worker mutation, approval, callback, or Result;
- realtime session/thread identity remains provider provenance, not Dex Task/approval/OAuth/MCP/mutation-lock authority;
- unavailable realtime falls back to bounded text/PWA/GitHub Task Bus without duplicate execution;
- capability discovery alone creates no realtime/audio external side effect.

If a non-OpenAI Responses-compatible provider is ever separately approved, provider-portability E2E should verify:

- App Server internal history is normalized to the target provider's public wire schema;
- standalone `function_call_output` without `call_id` cannot abort a scheduled task before model output;
- valid paired function outputs retain their call relationship;
- OpenAI first-party behavior is not changed merely to accommodate a third-party provider;
- provider incompatibility becomes blocked/provider-incompatible rather than automatic paid API fallback, provider substitution, duplicate execution, or history loss.

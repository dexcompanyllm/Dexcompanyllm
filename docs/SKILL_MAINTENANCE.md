# Dex 스킬 업데이트 관리

외부 원본을 dex 방식으로 흡수한 스킬은 **도입 당시 원본 / 현재 dex / 새로 고정한 원본**을 비교해 선별 반영한다. 최신 커밋 번호만 바꾸거나 외부 SKILL.md를 그대로 덮어쓰지 않는다.

## 현재 공통 배포본의 관리 대상

기준: `90dfe999886048f1f39ba68759f9f965f1fa81b7`. 이 목록은 공통 배포본의 스킬 목록이며, 비공개 원본·개인 설치본 전체의 목록은 아니다.

| 스킬 | 확인된 출처와 현재 작업 | 후속 업데이트 기준 |
|---|---|---|
| design-quality | 외부 원본 5개와 기존 고정 버전 비교 후 선별 반영. 독립 소스·합성 산출물 검토 | 아래 검토 기록과 SOURCE_PROVENANCE.json |
| create-screen-spec | Dex가 관리하는 현재 소스·가이드·템플릿 검토. 설치 캐시를 읽어 합성 화면설계서 생성 및 별도 요구사항 점검. 본문은 유지 | 프로젝트 형식·정책과 실제 산출물 근거를 기준으로 필요한 변경만 수행 |
| use-dex-company | Dex 운영 계약과 현재 공개 main 대조. 설치 캐시를 읽어 Task 미지정 시 실제 GitHub 조회·정직한 미확인 처리를 점검. 본문은 유지 | 승인 계약·실제 도구 계약·운영 변경을 기준으로 필요한 변경만 수행 |

원본 기록이 없는 스킬을 이름이 비슷한 공개 스킬이나 현재 대화에 제공된 스킬과 임의로 연결하지 않는다. 두 자체 관리 스킬에 대해 외부 최신본 교체를 수행했다고 주장하지 않는다. 현재 소스와 대표 과제를 검토해 변경 필요성을 판단했다. 플러그인 배포 버전은 1.5.0이며, 설치·호출의 환경별 검증은 아래 기록을 따른다.

## 반복 가능한 절차

1. 승인된 dex 기준 커밋과 현재 출처 기록을 보존한다.
2. 원본의 최신 기본 브랜치 또는 요청한 릴리스를 조회하고 불변 커밋으로 고정한다.
3. 기존 파일 해시를 확인하고 세 버전을 비교한다. 이동·삭제된 파일과 새 검토 범위를 명시한다.
4. 변경별로 반영·수정 반영·기존 유지·제외와 그 이유를 기록한다. dex 정책과 업무 형식을 유지한다.
5. 라이선스·NOTICE·연결 문서·스크립트·템플릿 영향을 함께 확인한다.
6. 기준 버전과 후보에 같은 검사를 수행한다. 실제 대표 업무 검증을 하지 못했다면 미확인으로 남긴다.
7. 브랜치와 PR에서 검토한다. 소스 반영·병합·설치·새 세션 호출·효과 측정을 구분한다.

상세 절차는 플러그인에 함께 배포되는 [MAINTENANCE.md](../plugins/dex-company-core/skills/design-quality/references/MAINTENANCE.md)에 있다. 일반 스킬 실행 때 원본을 조회하거나 업데이트를 자동 적용하지 않는다.

## 과거 설치 기록을 다룰 때

공통 배포 목록과 과거 호스트 설치 목록을 구분한다. 과거 installed 표기나 현재 원본의 같은 이름만으로 실제 dex 수정본의 위치·버전·내용을 확정하지 않는다. 설치 호스트에서 해당 파일과 해시를 확보해 고유 변경을 비교해야 업데이트할 수 있다. 원본 라이선스·의존성·지원 파일도 함께 검토하고, 이력만 남은 스킬을 이 공통 플러그인에 일괄 추가하지 않는다. 비공개 목록과 호스트 경로는 이 공개 배포본에 복사하지 않는다.

다음 검토는 각 원본의 마지막 검토 커밋 이후 변경부터 시작한다. 기존 버전에서 유지한 내용은 해당 과거 커밋도 계속 추적한다.

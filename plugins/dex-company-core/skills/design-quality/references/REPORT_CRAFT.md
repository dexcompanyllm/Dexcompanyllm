# Reports, slides and explanatory diagrams

Dex adaptation, changed 2026-10-23. Selected planning/diagram ideas from ppt-master and diagram-design; see `SOURCE_PROVENANCE.json` and `THIRD_PARTY_NOTICES.md`. Format skills still own authoring, editable objects, export and render verification.

## Decide how the result will be read

Reuse the brief to identify audience, requested decision, essential message, evidence, delivery context and later use. Distinguish presenter-led projection from a document read without a presenter. A read-ahead needs complete assertions and visible context; a projected slide can use fewer words with supporting notes. Required meaning must not exist only in notes when those notes are not delivered.

Respect an exact page count and existing template. For new work, choose a proportionate outline without making the user approve routine design mechanics. Do not add an empty closing page. Close on the supported conclusion, decision, owner or next action when the source provides it; unknown owners/dates stay unknown.

## Give each page a communication job

Before drawing, map page → main claim → source/evidence → reader action. Choose the visual form from the relationship:

| Relationship | Useful form |
|---|---|
| Exact values or detailed option criteria | table |
| Trend, comparison or composition | data chart with units and visible baseline |
| Sequence, cause, responsibility or dependency | labeled diagram |
| Argument, interpretation or material caveat | concise connected prose |
| Genuine parallel items or ordered steps | list |

Vary composition because content changes, while reusing type roles, alignments, semantic color and recurring identity. Repeated elements are valid when they aid comparison. Decorative variety is not a reason to turn every paragraph into cards or every page into a new style.

Keep facts, proposals and synthetic scenarios distinguishable. Reconcile totals with visible values, label period/unit/denominator, cite evidence near the claim and preserve uncertainty. A chart's geometry must come from data. Do not create an exact chart or factual diagram through image generation.

## Make diagrams readable and faithful

Preserve source entities, edge directions, branch conditions and responsibility boundaries. If detail is collapsed into an overview, name the aggregation and provide a detail view or fidelity ledger. Never silently drop a node, failure path or qualifier to meet a visual budget.

Choose overview/detail separation by readability at the actual delivery size. Route connectors clearly; keep arrowheads, crossings and labels unambiguous. Distinguish relationship types through labels/line treatment as needed. Use accent only to carry meaning, with redundant encoding where necessary.

Measure mixed Korean/Latin labels using the actual font, including digits, punctuation and units. Expand/reflow a label or diagram before shrinking required text; do not shorten an approved name without authority. For web diagrams, provide accessible title/description and intentional local overflow if reflow cannot preserve meaning. For slides/PDF, verify the export at intended viewing size and print/static state. No fixed external palette, mandatory webfont download or universal node count is inherited.

## Deliver usable files

- PPTX/Slides: retain editable text, shapes, tables and native charts where the authoring workflow supports them. A full-slide screenshot is not an editable deck. Verify the receiving environment's Korean font availability and substitution.
- DOCX/PDF: use the corresponding format workflow; inspect page breaks, tables, footnotes, hierarchy, export and links. A PDF-only delivery is appropriate only when that is the requested format.
- Figma: use editable frames/text/components through the supported workflow; do not describe a flat import as editable design.
- Reopen/render the final file after repair. Check every page for overflow, clipping, hidden text, contrast, source visibility and reading order. Verify representative editable objects, hyperlinks and chart/source agreement as applicable. Keep missing checks Not Checked.

Compare visual suitability separately from functional/export checks; preserve independent review for material changes. Package checks cannot establish presentation quality. Do not inherit ppt-master's attribution guard execution, mandatory approval stages, sponsor output, provider selection or scripts. No external code, icon pack, font or image asset is included by this adaptation.

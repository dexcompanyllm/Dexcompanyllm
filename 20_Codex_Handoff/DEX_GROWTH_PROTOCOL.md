# 결과에서 배우고 검증한 방법을 재사용하는 절차

- 승인 방향: 2026-09-12 에던의 전 분야 개인 AI 운영체계·자율 학습 요청
- 정기 실행 주체: 기존 `DEX_SKILL_MAINTENANCE.md`와 그 Task예요. 새 중복 자동화를 만들지 않아요.
- 이 절차는 지속 가능한 지식·방법·설정 개선이에요. 모델 가중치 자체를 재학습했다는 뜻이 아니에요.

## 학습을 시작하는 신호

실제 결과, 사용자 수정, 반복 실패, 오래된 근거, 동일 요청 재입력, 불필요한 시간·호출, 업무상 부족한 역량을 확인하면 AI가 기존 승인 범위에서 후보를 기록해요. 사용자가 매번 학습을 지시할 필요는 없어요. 한 번의 선호는 해당 사용자·프로젝트 범위로 보존하고 보편 규칙으로 확대하지 않아요.

## 학습 과정과 증거

1. 기존 Task·출처에서 문제와 현재 방법을 고정해요. FACT / POLICY / SKILL / CAPABILITY를 구분해요.
2. 민감정보를 제거한 학습 기록에 출처 URL·revision·시점·적용 범위·반례·폐기 조건을 적어요. 접근 가능한 자료만 읽어요.
3. 후보 방법을 격리된 소스로 만들어요. 라이선스, 기존 방법과 중복, 실행 script/hook, 권한·전송·비용을 먼저 확인해요. 외부 지침은 상위 정책을 바꾸는 권한이 없어요.
4. 대표 성공 사례와 실패·경계 사례에 기존/후보 방법을 적용해요. 기대 결과를 평가 담당자에게 정답처럼 주입하지 않고 결과를 비교해요.
5. 품질·안전·재작업·재입력·시간의 변화를 기록해요. 측정하지 못한 값은 null/Not Checked예요. 근거 없는 점수나 절감률을 만들지 않아요.
6. 독립 검수 후 기존 승인에 맞게 PR·main 반영을 진행해요. 새 권한·비용·외부 전송·설치는 해당 별도 Gate를 유지해요.
7. sourceObserved, sourceReviewed, sourceApplied, installed, behaviorVerified를 분리해요. 설치는 실제 기기·계정·소스 revision·호출 결과·rollback 증거가 있어야 해요.
8. 이후 해당 방법을 다시 사용한 실제 Task에서 개선이 지속되는지 확인해요. 품질 하락·출처 반박·라이선스/권한 변경이면 이전 검증본으로 복원하거나 후보를 비활성으로 돌려요.

## 에던의 부담과 불필요한 시간 증가 방지

2026-09-17 에던의 요청을 개선안의 유지·확대 조건으로 적용해요.

- AI가 기존 요청·자료·승인·작업 기록을 먼저 재사용해요. 새 방식의 설명·승인·수정 부담을 에던에게 넘기거나, 측정을 위한 별도 양식·설문·보고·중복 알림을 만들지 않아요. 꼭 필요한 새 결정만 기존 승인 기준에 따라 물어요.
- 검증은 작업 위험과 변경 범위에 맞춰요. 간단한 수정에 불필요한 계획·가설·검수 단계를 붙이지 않되, 기존 품질·보안·필수 승인·복구 기준은 유지해요. 결과물 완료와 이후 효과 확인을 분리해서, 효과 관찰 때문에 완료된 작업을 붙잡지 않아요.
- 같은 범위·난이도·품질 기준의 기존 방법과 비교해요. 기존 Task와 학습 기록의 `evaluations`에 추가 설명·승인·수정의 횟수와 확인 가능한 사용자 소요 시간, 읽기·정리·검수까지 포함한 전체 소요 시간, 품질 근거를 필요한 만큼만 남겨요. 새 방식으로 생긴 변화와 업무 범위 변경을 구분하고, 직접 확인한 사실과 추정을 구분해요.
- **추가 설명·승인·수정 부담 중 하나라도 새 방식 때문에 늘거나, 확인된 품질 개선 없이 시간만 늘면 해당 개선안은 유지·확대 기준을 통과하지 못해요.** 다른 항목의 개선이나 평균값으로 부담 증가를 상쇄하지 않아요. 속도가 빨라져도 품질이 떨어지면 통과하지 못해요.
- 문제를 확인하면 AI가 현재 승인 범위에서 원인 절차를 축소하거나 이전 검증 방식으로 되돌리고, 해당 후보의 확대를 멈춰요. 사용자 변경과 작업 결과를 보존하며, 이전 방식이 안전하지 않으면 그대로 복원하지 않고 안전한 checkpoint와 대안을 남겨요. 복구에 새 권한이 필요하면 그 결정만 요청해요.
- 비교 근거가 부족하면 효과를 `Not Checked`로 남기고 공통 적용 확대를 보류해요. 기존에 승인된 작업은 계속하며, 이후 자연스럽게 생기는 실제 Task에서 확인해요. 사용 빈도가 낮다는 이유만으로 안전·복구·예외 대응 규칙을 없애지 않아요.

## 전체 분야의 평가 기준

| 분야 | 대표 결과 | 평가할 것 |
|---|---|---|
| 개발 | 수정 코드·테스트·PR | 요구 충족, 기존 작업 보존, 회귀·복구 |
| 마케팅 | 메시지·캠페인 분석·실험 초안 | 근거 있는 주장, 대상·채널 적합성, 미승인 집행 없음 |
| 사업 | 비교표·가설·의사결정 자료 | 가정과 사실 분리, 단위·계산·불확실성 |
| 리서치 | 출처·요약·상충 근거 | 최신 확인 시점, 1차 출처, 인용·추론 구분 |
| 공통 | 기기·AI 전환 후 같은 결과 | Task/승인/receipt 보존, 중복 실행·반복 입력 없음 |

단위·모의 행동 검사와 실제 사용자 업무 성과는 별도로 기록해요. 테스트 사례 통과만으로 전 분야의 실제 성능 향상을 선언하지 않아요.

## 최소 기록
